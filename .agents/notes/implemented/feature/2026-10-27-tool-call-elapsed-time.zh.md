# Agent Note: 工具行显示该次调用的耗时

Status: implemented

[English](2026-10-27-tool-call-elapsed-time.md) | 中文

## 问题

对话 transcript（文本记录）中的工具行说明调用了什么、返回了什么，却从不说明这次调用花了多久。`ToolResultNode.callTime` 已经携带配对调用的开始时间戳，其契约也把该字段留给调用行的耗时，却没有任何行读取它。轨迹视图为每次调用渲染耗时，于是同一事实在一处可见，在用户真正阅读的那一处却缺失。盯着一个缓慢工具的人无法区分「快要结束」与「刚刚开始」。

## 决定

每个工具行在末尾承载该次调用的耗时：调用进行时显示实时计数，结果到达后显示它实际花费的时长。

时间戳来自 transcript 自身，它是计时的权威。运行中的行从已派发调用的开始时间戳起算；已结束的行从结果所配对的调用时间起算。调用时间被窗口截断而丢失的结果两者皆无，该行不显示标签——transcript 无法显示它并不掌握的耗时。

实时计数读取查看者自己的时钟，因此它可能与已结束的标签略有出入，后者由 Host 记录。它每秒跳动一次；标签使用代码字体，其等宽数字因此在跳动时不会左右抖动。

标签的单位取自 `conversation` 本地化命名空间，`ui-tool` 的行文案本就用它；格式与 chat 统计胶囊一致：不足一秒显示毫秒，不足一分钟显示带十分位的秒，超过一分钟显示分与秒。提问行不在此列，因为提问的耗时是人的等待时间，而非工具的工作时间。

## 考虑过的替代方案

- **由 Host 计算时长。** 已否决：Host 已记录两个时间戳，时长字段只是客户端本就能做的减法的第三种表示，而实时计数无论如何都需要查看者的时钟。
- **每一行都带标签，包括没有计时的调用。** 已否决：transcript 丢失开始时间戳的行随后会显示一个没有任何记录支撑的时长。
- **把计数放进行内的 shimmer。** 已否决：运行中的行会渲染两份内容——一份供辅助技术读取，一份是 aria-hidden 的扫光副本——因此其中的计数会同时跑两个定时器，扫光副本的跳动速度只有预期的一半。

## 后果

- transcript 无需打开轨迹视图即可回答「这花了多久」。
- 该标签与本就在可及名称中的退出码、增删统计并列，进入工具行的可及名称，辅助技术使用者因此能连同这一行一起听到耗时。
- 运行中行的计数与其已结束的标签可能相差查看者机器与 Host 之间的时钟偏移；已结束的值是记录下来的那个。
- 被窗口截断的调用不显示耗时，因此同一份 transcript 中会同时存在带标签与不带标签的行。
- 耗时单位现在存在于全部八种语言的 `conversation` 命名空间中，取值与 `chat` 命名空间一致。

## 测试

`packages/client/ui-tool/tests/tool-duration.client.spec.tsx` 覆盖从准备中、已派发到已结束块的计时推导、被窗口截断的结果、格式化器的三档阈值、标签在行尾的位置、假定时器下的实时计数，以及它在记录时长处冻结。

录制会话的黄金文件在各语言下都以 `{{duration}}` 记号收录该标签。中文的毫秒写法需要在既有的秒与分两种形式旁补一条归一化规则，中文黄金文件才会和其他语言一样折叠该标签。
